# Caddy Harness Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the real-Caddy APK release integration gate start and clean up reliably without cross-loop asyncpg connections.

**Architecture:** The pinned Caddy image is launched with an explicit executable. Uvicorn's worker loop owns a FastAPI lifespan that creates the disposable schema, seeds fixtures, serves the real release router, deletes its fixtures and disposes the engine before the loop closes. The synchronous caller owns only mounts, the Docker container and readiness/shutdown coordination.

**Tech Stack:** Python 3.12+, FastAPI, Uvicorn, SQLAlchemy asyncpg, PostgreSQL 17, Docker/Caddy 2.11.4, pytest.

**Spec:** `docs/superpowers/specs/2026-09-14-caddy-harness-lifecycle-design.md`

## Global Constraints

- Only `tests/deploy/caddy_harness.py` and its tests change; the production API, production DB, APK format and cutover logic do not.
- `require_caddy_database()` must validate the unique local `fitpilot_task_caddy_*` URL before any app/database import.
- The real `api.routers.releases.router`, exact production Caddyfile and fixed `CADDY_TEST_IMAGE` digest remain in the integration path.
- Never copy Firebase credentials into the runner or import the full `api.main` for the Caddy gate.
- Cleanup deletes only IDs generated by this harness and fails if it cannot prove completion.
- No production migration, API switch, APK publication or AAB build is part of this plan.

## File map

- `tests/deploy/caddy_harness.py`: guarded URL, Caddy command, ASGI app factory, single-loop FastAPI lifespan, readiness and shutdown ownership.
- `tests/deploy/test_caddy_database_bootstrap.py`: regression tests for schema/seed/request/delete/dispose loop affinity and startup failure cleanup.
- `tests/deploy/test_caddy_integration.py`: command-boundary test plus existing real Caddy GET/HEAD/range and security gates.
- `docs/superpowers/specs/2026-09-14-caddy-harness-lifecycle-design.md`: approved design; do not change its safety boundaries.

- [ ] **Step 3: Implement one-loop lifespan.** Make `_build_api_app` a synchronous factory invoked by Uvicorn in its worker thread. It imports only `fastapi`, `api.errors` and `api.routers.releases`; attaches the real router, error handler and `_TestControlRouter`. Its `@contextlib.asynccontextmanager` lifespan creates schema and seeds before `yield`, then deletes this instance's rows and disposes the engine in nested `finally` blocks. Remove all caller-side `asyncio.run(...)` database operations and caller-side row cleanup. Configure Uvicorn with `factory=True` and `lifespan="on"`.

```python
@contextlib.asynccontextmanager
async def lifespan(_app):
    try:
        async with database.engine.begin() as connection:
            await connection.run_sync(models.Base.metadata.create_all)
        await self._seed(database.SessionLocal, models.AppRelease)
        yield
    finally:
        try:
            if hasattr(self, "_session_factory") and self.release_ids:
                await self._delete_rows()
        finally:
            await database.engine.dispose()
```
